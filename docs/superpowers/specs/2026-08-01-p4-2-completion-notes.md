## 交付了什么

七个页面全部可用，菜单 `accounts/moderation/danmaku/custom/stats/logs/admin` 与路由
一一对应（Task 14 复核过，未发现偏差）：

| 页面 | 能用到什么程度 |
|---|---|
| 账号与直播间 | 全功能：扫码添加/续期账号、绑定直播间、参数调整、授权他人 |
| 房管 | 全功能：快捷禁言/解禁、禁言名单增删；「主播区」拉黑功能受限于后端接口未实现，标了「待后端支持」但控件不锁死；「自动禁言规则」跳转到自定义弹幕姬页并预填草稿（Task 14 接上，见下） |
| 弹幕姬 | 进房欢迎/礼物答谢/关注答谢/分享答谢/上舰答谢/轮播消息为真功能；PK 播报整体受限于协议层未解析（详见悬空清单第 10/11 条）；模板轮询、盲盒相关控件悬空 |
| 自定义弹幕姬 | 全功能的条件树可视化编辑器（触发器 + 模板任意组合），元数据从后端 `GET /api/meta/*` 拉取；「排除通用规则」悬空 |
| 统计 | 界面骨架就位，全部卡片显示占位符，不做假聚合；「盲盒盈亏」双重悬空 |
| 日志 | 历史查询 + SSE 实时事件流全功能；「清除」按钮受限于后端未提供删除接口 |
| 管理 | 改自己密码、用户管理（管理员）、授权管理（`member:manage`）全功能 |

保存与热重载（Task 13）已在弹幕姬 / 自定义弹幕姬两个有草稿态的页面统一接好：
右上角「保存并生效」→ GET 现有规则 → 合并（只替换本页管的那部分，不动别的页面
管的规则）→ PUT 写库 → POST 触发重载；第二步失败时有独立的持久提示，`dirty` 不
会被错误地归假。

**用户裁决贯穿全部页面**："后端接口统一最后处理，先看前台的开关和设置对不对"——
所以每个受限控件都**照常渲染、不 disabled**，用「待后端支持」黄色标签 + tooltip
说明具体缺什么；Task 14 把这些 tooltip 逐一过了一遍，补上了此前统一缺失的一个
维度：**区分"存了但引擎不认"与"连状态都不会保存、刷新/切换直播间就复位"**（详见
下面"Task 14 做了什么"）。

## 悬空清单：指路 + 哪几条需要用户真刷抓样本

完整的 15 条清单在 `docs/superpowers/specs/2026-08-01-p4-2-悬空清单.md`，每条列了
位置、具体缺什么字段/接口、补上之后前端改哪里。**这是后端补丁批次的直接输入**。

Task 14 把第 3 条（房管页"自动禁言规则"的跳转）标记为已解决——`Custom.vue`
现在真能从 query 参数预填一条可用的规则草稿，不再是"到得了地方但做不了标签
承诺的事"。**清单现存 14 条活跃悬空**，其余 14 条里，控制器凭现有代码信息就能
写出补丁方向，唯独下面 4 条是**控制器推不动的部分**——必须由用户在真实场景里
触发一次并抓包，否则写出来的解析代码是猜的：

- **第 7 条**：盲盒礼物单独一类 + 盲盒盈亏统计（弹幕姬·礼物答谢页）——需要真刷
  一次盲盒，且不是"随便刷一次"：盈亏必须按电池数量统计而非礼物名，滚动合并窗口
  内多次开出要同步重算，这两点也要靠真实报文验证字段形状之后才能定案（用户在
  项目记忆文件 `blindbox-profit-loss.md` 里对这条有明确要求，与本条完全对应）
- **第 10 条**：PK 匹配信息（对面主播昵称/直播间人数/大航海总数/在线数）——需要
  真实触发一次 PK 并抓包，字段名、在第几层都定不下来；即便字段补齐，"选择性
  播报其中几项"这个机制本身也还没设计，是双重缺口
- **第 11 条**：PK 串门欢迎——比第 10 条缺得更彻底，连"这个进场事件来自对面
  直播间"该怎么判断都还没确认，抓包之后可能还要另外设计一版，技术路线都未定
- **第 15 条**：统计页盲盒盈亏——与第 7 条同一个样本需求，不需要重复抓包，
  是同一份缺失协议数据在两处不同消费方（弹幕姬答谢文案 vs 统计页盈亏数字）上
  的体现，但还额外缺一层聚合接口（第 14 条），两层都要补才能显示真实数字

其余 10 条（模板轮询、单人/多人模板、`{{gifts}}` 变量、变量元数据接口、排除
通用规则的互斥机制、统计聚合接口等）都是纯后端能力/接口缺口，不需要抓包，
可以直接照清单里"补上之后怎么改"的描述实现。

## Task 14 做了什么（本次收尾的六件事）

1. **菜单/路由核对**：复核确认七个菜单 key 与路由 name 完全对应，用户此前的
   核对没有问题。`Shell.vue` 的 `go()` 里 `router.hasRoute` 判断现在对七个
   真实菜单项而言永远为真（"这个页面还没做"分支已经打不到），但作为防止未来
   新增菜单项时忘记注册路由的防呆保留下来，成本可以忽略；`Shell.test.ts` 的
   哨兵键 `'__never_registered__'` 测试原样保留，钉的是与具体页面数量无关的
   "go() 对未注册的 name 不抛异常"这个性质。
2. **房管页「去配置」按钮**：选了**接上预填**这条路。`Moderation.vue` 跳转时带
   `query: { preset: 'automute' }`，`Custom.vue` 用 `URLSearchParams` 读
   `window.location.search`（不用 `useRoute()`，因为本页大量测试直接
   `mount(Custom.vue)` 不挂 vue-router）识别到 `preset === 'automute'` 后插入
   一条「弹幕命中关键词 → 禁言 1 小时」的草稿骨架，关键词留空由用户自己填。
   只应用一次（`presetApplied` 标志），防止切换直播间导致 `loadRules` 重跑时
   重复插入。新增 4 条测试覆盖：预填出现且形状正确、无 query 时不插入、
   不重复插入、真实路由跳转带上了 query。
3. **全站悬空文案精修**：过了一遍全部「待后端支持」tooltip（`Danmaku.vue` 6 处、
   `PkPanel.vue` 2 处 + 顶部 `NAlert`、`Custom.vue` 1 处），逐个判断而非一刀切。
   结论：`pickMode`（进房欢迎/礼物答谢/轮播消息三处）、`multiTemplates`、
   两个盲盒勾选、PK 四个"播报哪些信息"勾选、PK 串门欢迎、以及 `Custom.vue`
   的「排除通用规则」——**全部**属于"连状态都不会保存"一类：这些字段从未被
   对应的 `buildXxxRule` 写进发往后端的 `Rule`，`parseXxxDraft` 也从不从已保存
   规则里恢复它们，所以刷新页面或切换直播间都会静默复位成默认值，不是"存了但
   引擎不认"。**这与简报原先给的例子不完全一致**：简报把 `Custom.vue` 的
   「排除通用规则」举例成"改动进了草稿、保存时也写进规则"这一类，但去读
   `buildCustomRule` 的实际代码后发现它压根不引用 `excludeBuiltinRules`——
   与 PK 那些勾选是同一种"连状态都不保存"，已经按实际代码行为改写了这处
   tooltip，并在这里如实记录这个订正。唯一真正落在"不生效但状态会保存"一类的，
   是 PK 播报的 `matchTemplates`（认领进"内置/PK播报"规则、会随整页保存写进
   数据库，PK 事件触发时确实会发弹幕，只是模板里的 `battle.opponentXxx` 变量
   在后端不存在、会渲染成空字符串）——这一点原来的 `NAlert` 文案写的是"整块都
   不生效"，也一并改成了准确描述。
4. **`docs/deployment.md`**：在已有的「Web 管理界面」一节里补了七个页面各自能
   用到什么程度、「待后端支持」标签的含义，以及热重载的具体操作步骤（右上角
   「保存并生效」按钮），保留了原文档已经写对的内容（`MAGICD_HTTP_ADDR` 默认值、
   首次登录密码来源、只监听本机等），没有整节覆盖重写。
5. **本文档**。
6. **构建与验证**：前端 210 个测试全绿（新增 4 条）、`typecheck`/`lint`/`build`
   全部干净，构建产物已跟着改动一起提交；后端 `go build ./...` 与全部 Go 测试
   （对本机 `localhost:5433` 的测试库）通过，六平台（linux/darwin/windows ×
   amd64/arm64，`CGO_ENABLED=0`）交叉编译全部成功。**端到端手工验证（起
   `magicd run`，扫码加账号 → 绑直播间 → 配规则 → 保存生效 → 看日志）跳过**
   ——需要真实 B 站账号与真实直播间，非本次能力范围内，留给用户自己走一遍。
