# P1 补丁：Docker 分发 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 补齐 P1 从未实现的 Docker 分发：多架构镜像、随 tag 自动发布、以及一份能把 PostgreSQL 一起带起来的生产 compose。

**Background:** 用户的原始需求明确列了 docker，P0 设计文档附录 C 的路线图里 P1 写的是「GoReleaser + Docker buildx，8 目标一键出包」，但 P1 被标记完成时 Docker 那一半从未做过——`.goreleaser.yaml` 没有 `dockers:` 段、仓库没有 Dockerfile、release workflow 没有任何 docker 步骤。由 P3 的 Task 19 审查间接发现（审查者发现 README 声称了不存在的能力）。

**Scope change vs 原 P1：** P3 把 **PostgreSQL 变成了硬依赖**，所以本补丁不只是「打个镜像」，还要解决「镜像怎么拿到数据库」和「首次启动怎么建表、管理员密码从哪看」。

## Global Constraints

- 二进制已经是 `CGO_ENABLED=0` 的静态链接，六平台交叉编译在 CI 里有守卫。**镜像只做 linux/amd64 与 linux/arm64**——其余四个目标是桌面二进制，不进镜像
- 镜像内的 `magicd` 与 Releases 里的二进制必须来自**同一次 GoReleaser 构建**，不得在 Dockerfile 里重新 `go build`。理由：两条构建路径迟早产出不同的东西，而"我下载的二进制和镜像里的行为不一样"是极难排查的一类问题
- 注释、文档一律用中文
- **验证命令一律用 `; echo "退出码=$?"` 而非 `&&`**
- 不改动 `server/` 下的任何 Go 代码。本补丁只碰构建、发布与文档

## 本计划自行定夺的决策

用户要求「做全套」但未指定细节，以下由控制器定夺，每条标出理由与推翻代价。

| # | 决策 | 理由 | 推翻代价 |
|---|---|---|---|
| 1 | 镜像推 **GHCR**（`ghcr.io/mrzhongzq/magicd`） | workflow 里现成的 `GITHUB_TOKEN` 就能推，不需要新建 secret；公开仓库免费；与代码同源同权限 | 小：换 registry 是改两处模板加一个 secret |

| 6 | 镜像**不内置 PostgreSQL** | 一个容器一个进程。数据库由 compose 里的官方镜像提供，或者用户接自己现成的 PG | 大：合进去等于自造一个难以维护的 all-in-one |

## Task 1: Dockerfile 与本地构建验证

**Files:**
- Create: `Dockerfile`
- Create: `.dockerignore`

**Interfaces:**
- Consumes: GoReleaser 在构建上下文里放好的 `magicd` 二进制
- Produces: 一个可运行的镜像；`docker run --rm <image> version` 能打印版本

### 为什么 Dockerfile 里不 `go build`

GoReleaser 的 `dockers:` 会先构建好二进制，再把它连同 `Dockerfile` 一起放进一个临时上下文目录，`COPY magicd /usr/local/bin/` 直接取用。

**不要**在 Dockerfile 里写 `FROM golang AS builder` 再 `go build`——那样镜像里的二进制和 Releases 里的就是两次不同的构建，ldflags 注入的版本信息也会对不上。

- [ ] **Step 1: 写 Dockerfile**

```dockerfile
# 运行时镜像。二进制由 GoReleaser 构建好后放进上下文，这里只做打包。
#
# 刻意不在这里 go build：那样镜像里的二进制与 Releases 里的会来自两次
# 不同的构建，ldflags 注入的版本信息也对不上，而「我下的二进制和镜像里
# 表现不一样」是极难排查的一类问题。
#
# 用 alpine 而非 scratch/distroless：这是自托管工具，用户需要能
# docker exec 进来看「为什么连不上 B 站」。没有 shell 的镜像排障时
# 只能干瞪眼，多出来的 7 MB 在一个带 PostgreSQL 的部署里可以忽略。
FROM alpine:3.20

# ca-certificates: 访问 B 站 HTTPS 接口必需
# tzdata:          定时规则（cron）按本地时区算，没有它一律是 UTC
RUN apk add --no-cache ca-certificates tzdata

# 非 root 运行。magicd 不需要任何特权，也不监听 1024 以下端口。
RUN addgroup -g 10001 magicd && adduser -D -u 10001 -G magicd magicd

COPY magicd /usr/local/bin/magicd

USER magicd:magicd

# 时区默认跟随宿主的 TZ 环境变量；未设置时是 UTC。
# 定时规则写的是几点几分，时区错了会整体偏移，部署时记得设。
ENV TZ=UTC

ENTRYPOINT ["/usr/local/bin/magicd"]
CMD ["run"]
```

**Files:**

- [ ] **Step 1: 在 `archives:` 之后、`checksum:` 之前插入**

```yaml
# 镜像只做 linux 两个架构：其余四个目标是桌面二进制，不进镜像。
#
# 每个架构先各推一个带架构后缀的 tag，再由下面的 docker_manifests
# 合成一个多架构 manifest——这样 `docker pull ghcr.io/mrzhongzq/magicd`
# 在 amd64 与 arm64 机器上都能自动拿到对的那个。
dockers:
  - id: magicd-amd64
    ids:
      - magicd
    goos: linux
    goarch: amd64
    dockerfile: Dockerfile
    use: buildx
    image_templates:
      - "ghcr.io/mrzhongzq/magicd:{{ .Version }}-amd64"
      - "ghcr.io/mrzhongzq/magicd:latest-amd64"
    build_flag_templates:
      - "--platform=linux/amd64"
      - "--label=org.opencontainers.image.title={{ .ProjectName }}"
      - "--label=org.opencontainers.image.version={{ .Version }}"
      - "--label=org.opencontainers.image.revision={{ .FullCommit }}"
      - "--label=org.opencontainers.image.created={{ .Date }}"
      - "--label=org.opencontainers.image.source={{ .GitURL }}"
      - "--label=org.opencontainers.image.description=神奇弹幕服务端：B 站直播弹幕机器人"
      - "--label=org.opencontainers.image.licenses=MIT"

  - id: magicd-arm64
    ids:
      - magicd
    goos: linux
    goarch: arm64
    dockerfile: Dockerfile
    use: buildx
    image_templates:
      - "ghcr.io/mrzhongzq/magicd:{{ .Version }}-arm64"
      - "ghcr.io/mrzhongzq/magicd:latest-arm64"
    build_flag_templates:
      - "--platform=linux/arm64"
      - "--label=org.opencontainers.image.title={{ .ProjectName }}"
      - "--label=org.opencontainers.image.version={{ .Version }}"
      - "--label=org.opencontainers.image.revision={{ .FullCommit }}"
      - "--label=org.opencontainers.image.created={{ .Date }}"
      - "--label=org.opencontainers.image.source={{ .GitURL }}"
      - "--label=org.opencontainers.image.description=神奇弹幕服务端：B 站直播弹幕机器人"
      - "--label=org.opencontainers.image.licenses=MIT"

docker_manifests:
  - name_template: "ghcr.io/mrzhongzq/magicd:{{ .Version }}"
    image_templates:
      - "ghcr.io/mrzhongzq/magicd:{{ .Version }}-amd64"
      - "ghcr.io/mrzhongzq/magicd:{{ .Version }}-arm64"
  - name_template: "ghcr.io/mrzhongzq/magicd:latest"

      - "ghcr.io/mrzhongzq/magicd:latest-amd64"
      - "ghcr.io/mrzhongzq/magicd:latest-arm64"
```

`{{ .GitURL }}` 会展开成仓库地址，`org.opencontainers.image.source` 标签让 GHCR 页面自动关联到仓库。

## Task 4: 生产用 docker-compose.yml

**Files:**
- Create: `docker-compose.yml`

**Interfaces:**
- Produces: `docker compose up -d` 即可跑起机器人与数据库

### 三个要解决的问题

1. **建表**：设计明确 `run` 不自动迁移（多实例下让每个实例各自决定何时改表很危险）。用一个**一次性 migrate service**——它恰好是「只有一个决定者」，不违背这条
2. **管理员密码**：`migrate` 只在空库上打印一次。在 compose 里它落在 migrate service 的日志里，必须在文档里告诉用户去 `docker compose logs migrate` 取
3. **启动顺序**：PostgreSQL 要先健康，migrate 要先成功，`magicd` 才能起

- [ ] **Step 1: 写 docker-compose.yml**

```yaml
# 生产部署：magicd + PostgreSQL。
#
#   1. cp .env.example .env   然后改掉 POSTGRES_PASSWORD
#   2. docker compose up -d
#   3. docker compose logs migrate    # 取管理员的一次性密码
#
# 与 docker-compose.dev.yml 的区别：那份是给本地跑测试用的，
# 端口 5433、密码写死 magicd/magicd、不含 magicd 本身。
# **不要把那份用于生产。**

services:
  postgres:
    image: postgres:16-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-magicd}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?请在 .env 里设置 POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB:-magicd}
    volumes:
      # 具名卷而非绑定挂载：绑定挂载在 Windows/macOS 上有 UID 与权限的老问题
      - magicd-pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER:-magicd}"]
      interval: 5s
      timeout: 5s
      retries: 12
    # 默认不对外暴露数据库端口。需要从宿主直连调试时再取消注释。
    # ports:
    #   - "127.0.0.1:5432:5432"

  # 一次性建表。设计上 magicd run 发现 schema 落后会拒绝启动而不自动迁移
  # （多实例部署下让每个实例各自决定何时改表很危险），所以用一个专职的
  # 一次性 service —— 它恰好是「只有一个决定者」。
  #
  # 空库上它还会创建管理员并打印一次性密码：
  #   docker compose logs migrate
  migrate:
    image: ghcr.io/mrzhongzq/magicd:${MAGICD_TAG:-latest}
    restart: "no"
    depends_on:
      postgres:
        condition: service_healthy
    environment:
      MAGICD_DATABASE_URL: postgres://${POSTGRES_USER:-magicd}:${POSTGRES_PASSWORD}@postgres:5432/${POSTGRES_DB:-magicd}?sslmode=disable
    command: ["migrate"]

  magicd:
    image: ghcr.io/mrzhongzq/magicd:${MAGICD_TAG:-latest}
    restart: unless-stopped
    depends_on:
      postgres:
        condition: service_healthy
      migrate:
        condition: service_completed_successfully
    environment:
      MAGICD_DATABASE_URL: postgres://${POSTGRES_USER:-magicd}:${POSTGRES_PASSWORD}@postgres:5432/${POSTGRES_DB:-magicd}?sslmode=disable
      MAGICD_LOG_LEVEL: ${MAGICD_LOG_LEVEL:-info}
      # 定时规则按本地时区算，时区错了规则会整体偏移
      TZ: ${TZ:-Asia/Shanghai}
```
